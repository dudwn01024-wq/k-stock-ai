# 추천 추세·거래량의 KIS 일봉 기준

이 문서는 분석 웹사이트의 추천 후보 계산에 적용되는 데이터 계약을 설명합니다. 실제 수익성이나 운영 수집 성공을 입증하는 문서가 아닙니다.

## 바뀐 자료와 유지한 계산

추천 추세·거래량은 Naver 일별 가격 대신 기존 `fetchKisDailyOHLCV`가 정규화한 KIS 일봉을 사용합니다. 화면 상단의 현재 시세도 KIS 현재가 조회 스냅샷이며, 추천 계산의 일봉 종가와 별도 출처·기준일을 갖습니다. 두 숫자를 같은 시점의 값이라고 간주하지 않습니다.

- 추세: 최근 종가 ≥ 5봉 이동평균 ≥ 20봉 이동평균.
- 거래량: 최근 일봉 거래량과 **최근 봉을 제외한 이전 20봉** 평균 거래량 비교. 최소 21봉이 필요합니다.
- 당일 낮은 거래량은 기존 15:40 KST 경계 전까지 장중 확인 대기입니다. 이 경계는 제공처가 일봉을 확정했다는 보장이 아닙니다.
- 현재 봉의 거래량이 이미 평균 이상이면 기존 장중 강세 확인 조건을 유지합니다.
- 기존 점수·등급·수급·뉴스·위험 관리 수식은 변경하지 않습니다.
- 과거 또는 휴장일 자료를 오늘 자료로 바꾸거나, 09시 이전에 오늘 봉을 만들어 넣지 않습니다. 실제 원천 거래일과 원래 조회 시각으로 계산합니다.

## 제한된 요청과 캐시 계약

요청은 기존 KIS 국내주식 일봉 API 경로를 사용합니다.

| 항목 | 고정값 또는 처리 |
| --- | --- |
| 경로 | `/uapi/domestic-stock/v1/quotations/inquire-daily-itemchartprice` |
| 요청 식별자 | `FHKST03010100` |
| 시장 요청 코드 | `J` |
| 주기 | `D` |
| 수정주가 요청 값 | `0` |
| 추천 읽기 프로필 | `maxBars:30`, `screeningSnapshot:true` |
| 일봉 데이터 요청 상한 | 종목당 1페이지, 1시도. 실패하면 재시도·Naver 대체를 하지 않음 |

`J`는 요청 코드 기록이며 실제 응답의 KRX/NXT 범위를 추가로 입증하는 표시가 아닙니다. API 요청 값은 보존하며 수정주가 방식을 임의로 변경하지 않습니다.

이미 상세 분석이 가져온 일반 130봉 이상의 일봉 캐시가 유효하고 종목·조회 기간·J/D/0 조건이 동일하면 최신 30봉을 재사용합니다. 진행 중인 동일 조건의 일반 요청도 공유할 수 있습니다. 기존 기본 캐시 유효기간은 15초이며 별도 관측용 요청·다른 종목·다른 기간·만료 자료는 가져다 쓰지 않습니다. 일반 상세 분석의 페이지 수와 재시도 정책은 그대로 유지됩니다.

추천 한 회차에서 같은 종목의 빠른 검사와 후속 계산은 동결한 동일 스냅샷을 재사용합니다. 캐시를 읽었다는 이유로 `receivedAt`을 현재 시각으로 새로 만들지 않습니다. 따라서 늦게 재사용된 장중 봉이 시간 경계를 넘었다는 이유만으로 완료 봉처럼 바뀌지 않습니다.

위의 1회 상한은 **일봉 데이터 HTTP 요청**에 대한 것입니다. 기존 인증 토큰이 없거나 만료되었을 때 필요한 OAuth 토큰 발급은 별도이며 기존 토큰 캐시를 유지합니다. 새로운 실제 호출이나 비용 검증을 수행했다는 뜻은 아닙니다.

## 데이터가 부족할 때

원천 최신 행의 완전성, OHLC 가격 관계, 거래량 정수·0/null 구분, 거래일 중복·불일치, 명시적 시간대가 있는 조회 시각을 검사합니다. 자료가 부족하거나 검증에 실패하면 데이터 부족 또는 조회 실패를 반환합니다. 다른 제공처 숫자, 최신이라는 추정 날짜, 평균 거래량으로 메우지 않습니다.

현재 기존 KIS 읽기 경로는 **숫자 6자리 종목 코드**만 지원합니다. Naver 후보 목록의 영숫자 코드는 원래 코드를 변환하지 않고 `KIS_SYMBOL_UNSUPPORTED`로 남깁니다. 지원 범위를 확장하려면 해당 제공처의 종목 식별·지원 계약을 별도로 검증해야 합니다.

## 추천 성과 수집은 별도 보류

기존 추천 성과 수집기는 Naver 일별 종가 전용입니다. 새 추천 기준 가격을 KIS로 저장하면서 이후 수익률을 Naver 종가로 계산하면 제공처를 섞게 됩니다. 이를 막기 위해:

1. 새 기준 가격에 KIS 제공처와 J/D/0 요청 조건을 저장합니다.
2. 기준일 당일 종가는 기존 정책대로 확정 가격 없이 `DAILY_CLOSE_PENDING` 상태로 저장합니다.
3. KIS 기준 기록은 기존 Naver 성과 수집 대상에서 제외하고 `TRACKING_BLOCKED_PROVIDER_MISMATCH`로 구분합니다. 실행 모드여도 그 기록 때문에 Naver 일봉을 호출하지 않습니다.
4. 기존 Naver 기준의 확정 기록과 이미 저장된 성과는 유지합니다.

**KIS 전용 성과 수집을 새로 구현하거나 실행한 것은 아닙니다.** 같은 제공처의 이후 확정 일봉·기업행동·기간 정책을 검증해 연결하기 전까지 새 KIS 추천의 T1/T5/T20 성과 수집은 보류됩니다. 이 작업의 가상 회귀 검사는 자료 분리와 수식·캐시·요청 제한을 검증하며 실시장 성과나 수익성 개선을 검증하지 않습니다.
