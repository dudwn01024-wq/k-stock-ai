# KIS 공식 지원 문의 초안 — 미발송

이 문서는 공개 API 계약에 관한 질문만 포함한다. 계좌·인증정보나 실제 응답을 첨부하지 않는다.

1. H0STCNI0 개별 체결을 유일하게 식별할 공식 체결번호/순번이 있는가? 동일 초·가격·수량의 분할체결과 재전송을 어떻게 구분하는가?
2. H0STCNI0의 공급자 거래일은 어떤 필드로 확인하는가? 체결시간만으로 날짜를 보완하지 않는 방법이 있는가?
3. WebSocket 끊김 이후 누락 체결 재생 또는 개별 체결 단위 복구를 지원하는가?
4. 일별 미체결, 정정취소가능주문, 예약주문 조회를 합쳐도 남는 주문 종류·상태는 무엇인가? 전일 주문, NXT/SOR, 정정·취소 처리 중 및 특수 주문의 포함 범위는 무엇인가?
5. 주문가능현금/미수없는매수금액에 미체결 예약금이 이미 차감되는가? 계좌 전체 현금으로 사용할 수 있는가?
6. BALANCE와 UNFILLED 계좌 상태의 공급자 기준일·기준시각 및 두 응답의 동일 시점 여부를 확인하는 방법이 있는가?
7. nass_amt의 계좌 유형별 부채·신용·대출 포함 범위는 무엇이며 총평가금액과 어떻게 다른가?
8. HTS/MTS 수동 주문의 체결도 동일 실시간 체결통보에 포함되는가? 앱 주문과 식별하고 전체 누락 여부를 검증할 수 있는가?

## 이번 foundation의 범위

공식 ZIP의 examples_llm/domestic_stock/inquire_psbl_rvsecncl 및 order_resv_ccnl을 참고했다.
각각 GET TTTC0084R / CTSC0004R, output 목록, FK/NK100 / FK/NK200을 사용한다.
VTS 대응 계약은 이 두 예제에서 확인하지 못했으므로 새 fixture parser는 LIVE 환경만 허용한다.
실제 요청 실행기는 없으며 시작/종료 날짜는 fixture 범위 설명일 뿐 공급자 기준일이 아니다.
기존 일별 미체결 candidate는 이미 검증된 객체만 받는다. 해당 candidate가 보존하지 않는 주문 ID나 조회 날짜를 복원하지 않는다.
psbl_qty와 예약주문은 일반 pendingOrders로 변환하지 않는다. 동일 주문번호도 합치거나 중복 제거하지 않는다.
모든 조회가 완료되어도 전체 coverage, authoritative pendingOrders 및 Risk readiness는 false다.
선택적 예약 메타데이터가 없거나 형식이 불명확하면 null이며, 정상 조회 완료는 해당 필드의 완전성이나 전체 주문 범위를 뜻하지 않는다.
