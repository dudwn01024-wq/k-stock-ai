# KIS 추천 수급 공급자 전환 — 로컬 검증용 설계

구현 기준은 0ef2a24다. 최초 구현 단계는 로컬 코드·mock 검증에 한정했고, 운영전환은 후속 명시 승인 후 OFF 초기화→ON 활성화 순서로 진행한다. 강제 금융 조회나 새500종목 분석은 배포 검증에 포함하지 않는다.

현재 예약 패널은 추천 목록 아래에 있지만 foreground 등록·150초 heartbeat·프로세스 메모리에 의존한다. 이를 추천 결과 저장·갱신 경로로 바꾼다. 로그인·브라우저·등록 버튼은 예약 실행 조건이 아니다.

## 후보와 호출 범위

- expanded500의 기존 가격·거래량 사전 순서로 뽑힌 심층 후보 기본40/최대60을 모두 보존한다. 수급 때문에 최종 추천에 들지 못한 후보도 포함한다. 선택종목1개를 합쳐 최대61이다.
- 사용자 분석 완료 때 후보 풀을 교체한다. 회차 갱신은 이 풀의 KIS 수급만 조회하고 기존4점 조건·등급·정렬로 재평가한다. 풀 밖 종목의 진입은 새로운 기존 분석이 후보 풀을 생성할 때 가능하다. 이미 추천된 종목만 순환하는 구조가 아니다.
- 회차당500종목 분석, 가격·뉴스·Gemini 무인 재조회는 추가하지 않는다. 추가 자동 provider 호출 상한은0이다. 기존 수동500 분석은 별도 비용이며 회당 universe≤10, price≤500, 심층≤60의 기존 요청 정책을 따른다. 무인 후보 풀 새 생성은 추가 provider 예산을 설계·승인한 후의 별도 범위다.
- KIS 기존610수급/일·인증 포함1220HTTP/일·동시1·최소2초·회차당종목최대2회·지연+7분·+12분 종료와 영속예산을 유지한다. 기존 미확인 달력의 첫 회차 제한 probe 및 휴장·특수장·당일성 보류를 유지하고 날짜를 추가하지 않는다.

## 저장과 실행

기존 검증된 Render /var/data 디스크에 별도 제한된 checksum/원자적 state 파일을 둔다. 새 코드의 KIS_AUTONOMOUS_RECOMMENDATIONS_ENABLED는 기본OFF다. OFF 단계에서 저장소를 초기화하며 ON 단계에서 저장소·영속예산이 준비되지 않으면 실행하지 않는다. 전환 시 이 새 스위치만 조정하고 기존 서비스·디스크·조회 한도·Auto Deploy 설정은 유지한다. 시작 로그의 후보 수·출처 실행 ID·저장소 준비 상태로 복원 여부를 읽기 전용 확인한다.

후보의 원래 가격·차트·뉴스 근거, 공급자 출처, 선택종목, 검증된 normalized KIS 관측과 당일 첫 회차 증거, 최신 재평가 목록·순위를 저장한다. 재시작은 이 자료만 복원하고 금융 재스캔을 시작하지 않는다. 구독 TTL/heartbeat/로그인 만료/브라우저 종료는 서버 작업을 중단하지 않는다. 손상·쓰기 실패·이전날/미수신 자료는 수급 확인 대기/자료 부족이며 NAVER fallback은 없다.

새 추천 계산은 항상 KIS assessment를 사용한다. NAVER integration 수급 요청·파싱·판정 fallback을 추천 경로에서 제거한다. NAVER 가격·뉴스 공급자 및 주문/Risk Manager/SEO/보안은 유지한다. 기존 NAVER 기반 이력은 과거 기록으로 분리하고 자동으로 새 KIS 후보 풀이나 현재 결과로 승격하지 않는다.

## 표시와 검증

추천 화면 상단에서 서버 자동 갱신·후보 수·저장 상태와 최종 관측 결과를 확인한다. 등록 버튼이나 화면 유지 요구는 없다. 캐시 조회는 금융 조회를 실행하지 않는다. 수급 카드에 원천 거래일(제공되지 않으면 미확인), 실제 서버 조회시각 KST, 관측일 추론, 입력 회차, 추정/대기/실패·휴장 상태를 따로 표시한다. 원천 제공시각이 없는 데이터에 가짜 시각을 넣지 않는다. 장 마감·이전날 저장 결과는 마지막 관측 당시 결과로 명시한다.

mock 검증은 무브라우저·무로그인·재시작·모바일 종료 후 예약, 순위 저장과 재접속 표시, 수급 탈락 후보의 신규 진입, NAVER 미사용, 지연/휴장/당일성 불확실, 저장 실패, 예산 상한·재시작 중복 방지를 포함한다. 실제 운영전환 전에 사용자에게 이 무인 실행 범위와 별도 실제 검증 계획을 보고한다.
