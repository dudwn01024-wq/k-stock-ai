# 상세 분석 근거와 저장 수급 분리

## 확인된 문제와 실제 원인 미확정

사용자 화면으로 선익시스템 `171090`을 확인했다. 2026-10-19 16:10:28.095 KST 당일 일별 수급 READY 기록은 있으나, 상세 화면은 추세·거래량·뉴스 미확인과 가격 계획 없음, 일반적인 ‘저장 수급·대기’ 이유만 표시했다. 보호된 실제 저장 응답과 당시 상세 원문을 읽지 못해, 원래 상세 전략이 불완전했는지 이후 빈 재평가가 덮었는지는 확정하지 않았다. 추가 화면은 설계 근거로 충분하며 같은 스크린샷을 다시 요구하지 않는다.

실제 매퍼·엔진·병합 함수로 두 경로를 합성 재현했다. ATR 하나만 부족해도 엔진은 기술·시장 판정과 가격 계획이 비어 있는 전략을 반환한다. 또 기존 병합은 수급 재평가의 null 판정·가격 필드를 원본 전체 위에 덮었다. 마지막에는 원래 DATA_INSUFFICIENT/무결성 사유까지 일반 WAIT 문구로 대체해 원인을 숨겼다. 화면의 빈 가격은 원천 ATR·지지·저항이 전부 없었다는 증거가 아니다.

## 최소 수정

운영 변경은 프런트 두 파일뿐이다.

- `frontend/src/utils/detailSupply.js`: 원본은 `originalDetail`로 분리해 보존한다. 수급 전용 projection은 동일 종목·수급 원천·영업일·조회시각에 일치하는 수급 조건만 전달한다. projection의 차트·가격 계획·뉴스·기타 조건은 원본을 대체하지 않는다. null 또는 불완전 응답으로 원래 기술·거래량·뉴스 판정이 지워지지 않는다.
- 같은 함수는 원본 상세 부족/무효 가격 계획의 사유를 유지하고, 원본에 반환되지 않은 ATR·지지·저항은 ‘미확인 입력’으로 표시한다. 실제 원천 값의 부재를 단정하거나 새 값을 추정하지 않는다.
- `detailReference`는 원래 기준일과 상태를 담는 참고 역할이다. 서버 기준일과 다른 원본은 이전 자료로 표시한다. 캐시 조회시각을 원래 차트·뉴스의 최신 시각으로 바꾸지 않는다. 이전 거래일 READY 캐시는 현재 수급값/점수로 재사용하지 않는다.
- 가격을 현재 판정에 사용할 수 없는 경우 가격 기준·파생 비율·손익비 상태를 함께 비활성화한다. 다른 시각의 projection 가격을 가져와 빈 원본을 채우지 않는다. 원래 서버 상세와 현재 수급이 동일한 경우에도 전체 신호는 계속 WAIT이며, 보존된 조건은 현재 판정에서 제외된다.
- `frontend/src/CurrentAnalysisSummary.jsx`: 원래 분석 조건과 저장 수급의 역할을 구분한다. 원래 조건에는 ‘원래 분석’을 붙이고 기준일·현재 판정 제외를 명시한다. 단순 ‘대기’ 대신 상세 자료 또는 상세 판정 확인이 필요함을 표시한다. 원래 부족 사유는 요약과 기존 상세 패널 양쪽에 표시된다.

서버 엔진·가격/ATR 계산식·점수·Risk·뉴스·주문·계정·종목 목록·KIS 스케줄/2초 간격·공유 예산·원장·provider 요청 경로는 `e70e194203bd9e3922e3642f51567a32eda9a20a`와 같다. 수급 정상 완료를 전체 상세 분석 완료나 매수 허가로 승격하지 않는다. 실제 조회시각·원천 거래일·sourceUpdatedAt 미확인·finality UNKNOWN 및17:10 미도착 재확인 정책을 유지한다.

## 회귀와 화면 검증

`tests/detail-supply-preservation.test.cjs`는 실제 App 매퍼, 상세 엔진, 병합 함수와 요약 렌더러를 사용한다. ATR 하나 부족, 원본 정상+캐시, null/빈/ATR 부족 projection, 불완전 원본의 다른 projection으로 채우기 금지, 종목·조회시각·거래일 불일치, 이전/미래 거래일 캐시, 오래된 원본, 무결성 부족, null 개별 조건, 반복 캐시 읽기 및 no-entry를 검증한다. 기존 projection 회귀도 수급 전용 역할에 맞게 가격/뉴스를 빌려오지 않는지 확인하도록 갱신했다.

과거 소스 경계에는 이번 두 파일만 SHA-256과 정확한 역변환으로 기준 버전을 복원한다. 다른 프런트나 서버 변경을 포괄적으로 제외하지 않는다. 종전 universe 패치의 ‘UI 무변경’ 회귀도 이 정확한 복원을 거친 두 파일 외에는 기존 byte 비교를 유지한다.

현재 코드 기준 집중151/151, 소스 경계·관련 회귀38/38, 전체123 suites 2,711/2,711 및 production build가 통과했다. 새 전용 회귀19개가 전체 실행에 포함됐다. PC1440/모바일390에서 정상 원본, ATR 부족, null projection, 조회시각 불일치, 이전 거래일 캐시, 원본 무결성 부족의12개 조합을 확인했다. 원래 사유·참고 표시·이전 자료 구분·가로 넘침/페이지 오류 없음·승격 없음이 검증됐다. 상세 로드 버튼은 loopback 모의 API에만 연결하며 실제 상세/금융 API는 호출하지 않았다. 최종 집계와 증거는 `../detail-preservation-evidence/result.json`에 기록한다.
