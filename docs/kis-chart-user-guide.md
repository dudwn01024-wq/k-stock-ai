# KIS 기간 차트 사용 안내

이 문서는 로컬 구현 기준이다. GitHub 업로드·Render 배포·실제 종목 시세 확인이 완료됐다는 의미가 아니다.

## 봉 하나가 뜻하는 기간과 화면 범위

표시 주기는 **일봉(D)·주봉(W)·월봉(M)·년봉(Y)** 네 가지다. 일봉은 봉 하나가 하루, 월봉은 봉 하나가 한 달의 가격 움직임을 나타낸다. 한 달치 일봉을 보고 싶다는 뜻과 월봉을 선택한다는 뜻은 다르다. `3M`이나 분봉·초봉·틱은 이번 기능의 지원 대상이 아니다.

주기는 KIS에 해당 원래 주기로 요청한다. 일봉 몇 개를 앱에서 모아 주봉·월봉·년봉처럼 만드는 방식이 아니다. 한국투자증권의 [공식 기간별 시세 API 예제](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/inquire_daily_itemchartprice/inquire_daily_itemchartprice.py)는 D/W/M/Y와 1회 최대 100건, 수정주가 요청 구분을 설명한다. 이 구현도 한 응답에서 받은 실제 봉을 최대 100개까지만 사용한다. 상장일부터의 전체 과거 자료를 확보했다고 표시하지 않는다.

`최근 20봉`, `최근 40봉`, `최근 60봉`, `받은 봉 전체`는 **이미 받은 봉 안에서 화면에 보일 개수**를 바꾼다. 예를 들어 월봉 30개를 받은 뒤 `최근 20봉`을 선택하면 최근 20개월 봉을 보여 준다. `받은 봉 전체`도 받은 30개를 뜻하며 없는 옛 자료를 새로 조회하거나 만들어 내지 않는다. 실제 받은 자료가 더 적으면 그만큼만 보인다.

## 확대·이동·가격 확인

아래는 이 사이트가 직접 구현한 차트의 조작법이다.

1. `＋ 확대`는 한 화면에 보이는 봉 수를 줄여 자세히 본다. `− 축소`는 받은 봉 안에서 더 넓게 본다.
2. `← 과거로`, `최근으로 →` 버튼으로 표시 범위를 옮긴다. `보기 초기화`는 최근 최대 60봉 보기로 돌아간다.
3. 기본 `값 확인` 모드에서는 봉을 마우스로 가리키거나 눌러 날짜·시가·고가·저가·종가·거래량을 확인한다. 모바일의 세로 페이지 스크롤을 막지 않는다.
4. `차트 끌어 이동`을 선택하면 차트 안에서 좌우로 끌어 받은 범위를 이동한다. 이 모드에서는 세로 페이지 이동을 차트 바깥에서 한다. 다시 `값 확인`으로 돌아갈 수 있다.
5. 키보드는 좌우 방향키로 봉 선택, Home/End로 받은 첫·마지막 봉 선택, `+`/`-`로 확대·축소한다. Escape는 끌기 모드를 종료한다.

확대·이동·봉 선택·MA 표시 변경은 새 시세 요청을 만들지 않는다. 두 손가락 확대나 휠 조작 등 구현하지 않은 동작을 지원한다고 안내하지 않는다.

주기와 표시 범위를 구별하고 받은 봉 수를 알리는 사용 방식은 [한국투자증권 공식 일반차트 도움말](https://www.truefriend.com/pro_help/0300.html)의 주기 선택·조회 봉 수·확대·이동 설명을 참고했다. 이 사이트는 자체 React/SVG 구현이며 한국투자 앱·HTS 전체 기능이나 동일한 터치 조작을 구현했다는 뜻은 아니다.

## 이동평균선과 분석 기준은 별개다

차트의 MA5·MA20·MA60은 **선택한 표시 주기의 종가**를 각각 5개·20개·60개 평균 낸 값이다. 월봉 MA20은 20개월 봉의 평균이며, 일봉 MA20은 20일 봉의 평균이다. 앞선 봉이 부족하면 숫자를 채우지 않고 `미확인`으로 남긴다. 평균 계산에는 받은 전체 자료를 쓰고, 화면 확대는 그 결과 중 보이는 부분만 바꾼다.

차트를 주봉·월봉·년봉으로 바꿔도 종목의 상세 분석, 패턴·엘리엇·가격 시나리오, 기존 진입 판단이 그 주기로 다시 계산되지는 않는다. **표시 주기는 선택한 주기, 분석 기준은 계속 KIS 일봉**이라고 구별한다. 화면 상단의 별도 현재가와 차트 봉의 종가는 제공처·거래일·수신 시점이 다를 수 있으므로 각 출처 표시를 함께 읽는다.

## 출처·기준일·진행 중인 봉

차트는 `KIS_NATIVE_PERIOD_OHLCV` 원천, 응답으로 확인한 종목, 요청 주기·수정주가 구분, 봉 날짜, 수신 시각을 검사한다. 요청 범위와 실제 봉 날짜 목록을 받으면 서로 맞는지도 검사하고 화면 쪽 메타데이터에 보존한다. 원천 시각이 없으면 수신 시각으로 바꿔 쓰지 않는다. 수신 시각은 “사이트가 받은 때”이며, 원천 시각은 “제공처가 그 값에 붙인 때”다.

- 현재 한국 날짜의 일봉, 현재 한국 달력 주·월·년 구간의 봉은 `진행 중 잠정 봉`이다. 가격과 거래량이 이후 바뀔 수 있다.
- 과거 기간 봉도 **제공처의 최종 확정을 검증한 것은 아니다**. `calendarIncomplete: false`는 현재 달력 구간이 아니라는 뜻이며 확정 시세 보장이 아니다. 원천 확정 상태는 `UNCONFIRMED`로 남긴다.
- 거래량 0은 실제 숫자 0으로 보존한다. 필수 OHLCV가 누락되거나 잘못된 날짜·중복 주기·다른 종목이 오면 다른 봉으로 보수하거나 조용히 제외하지 않고 해당 차트 응답을 오류로 처리한다.
- 시장 범위는 응답으로 검증되지 않았으므로 `UNKNOWN`을 유지한다. 종목의 KOSPI·KOSDAQ 구분이나 요청 코드만으로 KRX·NXT 범위를 확정해 표시하지 않는다.

## 종목·주기 변경과 오류 처리

새 종목이나 주기를 고르면 이전 봉과 출처를 즉시 비우고 새 조회 상태를 표시한다. 같은 종목·주기의 **진행 중 요청만** 하나로 공유한다. 이전 요청을 취소하고, 취소를 무시한 응답이 늦게 도착해도 현재 종목이나 주기 위에 표시하지 않는다. 종목 A → B → A로 빠르게 돌아와도 첫 A의 낡은 응답을 채택하지 않는다.

프런트 요청은 기본 20초에 제한하며 KIS 데이터 조회의 서버 시간 제한과 구분한다. 오류나 시간 초과 뒤 자동 재시도·주기적 새로고침·Naver 대체 조회를 하지 않는다. 사용자가 `선택한 주기 다시 조회`를 눌렀을 때 새로 요청한다. 조회 중에는 `조회 취소`로 화면 요청을 종료할 수 있다. 차트 오류가 별도의 상세 분석·AI 해설 결과를 지우거나 새 AI 호출을 만들지는 않는다.

## 로컬 검증 범위

요청 제어기는 `frontend/src/utils/kisChartRequest.js`, 검사는 `tests/kis-chart-request.test.cjs`에 있다. 2026-10-29 실행에서 **24개 통과·실패 0·skip 0**을 확인했다. 가짜 fetch와 직접 제어하는 가짜 타이머로 D/W/M/Y, 0과 결측, 출처·종목·날짜·원래 주기, 중복·비정상 OHLCV, 연속 종목·주기 전환, 동일 요청 공유, 늦은 응답, JSON 처리 중 취소, 화면 해제, 명시 재조회, 정지한 전송의 시간 초과를 검사했다. 실제 KIS 리더 소스도 가짜 환경·응답에 격리해 네 주기 모두를 요청 제어기까지 연결하고 계약이 일치하는지 검증했다.

이 하위 검사는 실제 금융·AI·계좌·주문 API를 호출하지 않았다. 실제 KIS의 오늘 데이터 정확성, 운영 로그인 뒤 화면, 전체 빌드, 실제 모바일 브라우저의 조작 검증은 상위 통합 작업에서 구분해 확인해야 한다.
