# 분석용 조건부 가격 시나리오와 손익비

이 문서는 `services/analysisPriceScenarios.js`의 실제 구현을 설명합니다. 신규 시나리오는 기존 추천 점수·상세 판정·Risk Manager·주문 허용을 바꾸지 않습니다. 기존 가격 계획은 `legacyPricePlan`으로 원본을 보존합니다. 신규 출력은 모두 `analysisOnly: true`, `orderPermission: false`입니다.

## 무엇이 달라지는가

기존 상세 계산은 지지선·저항선·ATR을 사용했습니다. 신규 분석은 새 차트 패턴의 **각각 다른 조건과 근거**를 별도로 보여 줍니다. 서로 다른 후보를 평균 내거나 손익비가 가장 큰 후보를 자동 선택하지 않습니다. 상승·하락 후보가 함께 있으면 `OPPOSITE_DIRECTION_CANDIDATES`로 표시하고 모두 유지합니다.

- 상승 패턴: 관측된 저항 또는 목선의 돌파 참고값 → 패턴 구조가 깨지는 경계 → 패턴 높이로 계산한 목표 참고값.
- 하락 패턴: 관측된 지지 이탈 참고값 → 구조가 깨지는 위쪽 경계 → 아래쪽 목표 참고값. 이는 하락 관찰용이며 공매도 허용이 아닙니다.
- 재시험: 후보를 알 수 있었던 시점 이후, 돌파 다음 일봉의 고가·저가가 기준선을 포함하고 종가가 돌파 방향에 남은 경우를 관측합니다. 정밀한 장중 순서나 체결을 주장하지 않습니다.
- 변동성: 입력된 양수 ATR14를 참고 정보로 표시합니다. 신규 시나리오의 손절 폭을 임의로 늘리거나 줄이지 않습니다.
- 하라미처럼 표준 측정 목표를 제공하지 않는 후보: 알려진 참고값만 보존하고 손익비를 만들지 않습니다.
- 엘리엇·ABC: 모든 피보나치 참고 구간과 관측된 무효 경계를 보존합니다. 파동 자체에는 확정된 진입·목표가 없으므로 `REFERENCE_ONLY`/`ELLIOTT_ENTRY_NOT_CONFIRMED`로 표시합니다. 단순히 5파가 관측되었다는 이유로 매수·매도 가격을 만들지 않습니다.

지지·저항의 역할 전환과 재시험 해석은 [CME의 지지·저항 교육](https://www.cmegroup.com/education/courses/technical-analysis/support-and-resistance)을 참고했습니다. 돌파·재시험의 구체적 일봉 조건, 후보 보존 방식, 상태 코드는 이 프로젝트의 명시적 구현 규칙이며 수익성이 입증된 전략이라는 뜻은 아닙니다.

## 진행 중·확인·무효·불명확의 뜻

후보의 원본 상태는 `candidateStatus`에 그대로 둡니다. 별도 시나리오 상태는 다음과 같습니다.

| 상태 | 실제 의미 |
| --- | --- |
| `CONDITIONAL` | 진입·무효·목표의 계산 순서가 유효한 조건부 참고값. 주문이나 체결 확인이 아님 |
| `REFERENCE_ONLY` | 파동 참고 구간 또는 가격 근거 일부만 존재. 진입·목표를 만들어 채우지 않음 |
| `INVALIDATED` | 원본 후보가 무효이거나, 후보가 정의한 **종가 무효 규칙**이 이후 완료 일봉에서 관측됨 |
| `AMBIGUOUS` | 후보가 불명확하거나 한 일봉 안에서 손절 경계·목표가 함께 닿아 장중 순서를 알 수 없음 |
| `UNAVAILABLE` | 가격 순서·날짜·단위·후보 근거가 검증되지 않음 |

패턴이 “완료 일봉 종가가 경계 이하”를 무효 조건으로 쓰면 저가만 경계 아래로 내려갔다고 구조를 무효로 바꾸지 않습니다. 저가·고가의 경계 접촉은 `observations.stopBoundary`에 별도로 표시하며, 실제 손절 체결이나 손실 확정을 가정하지 않습니다.

## 손익비 수식과 쉬운 가상 예

단위는 원/주(`KRW_PER_SHARE`)입니다. 결과의 `ratio`는 **보상 ÷ 위험**이며 승률·수익률 예측이 아닙니다.

상승 관찰:

```text
위험 = 진입 참고값 − 손절/무효 참고값
보상 = 목표 참고값 − 진입 참고값
gross 손익비 = 보상 / 위험
필수 순서: 0 < 손절 < 진입 < 목표
```

하락 관찰:

```text
위험 = 손절/무효 참고값 − 진입 참고값
보상 = 진입 참고값 − 목표 참고값
gross 손익비 = 보상 / 위험
필수 순서: 0 < 목표 < 진입 < 손절
```

TEST_ONLY 예: 상승 진입 10,000원, 무효 경계 9,800원, 목표 11,000원이면 보상 1,000원 ÷ 위험 200원 = **5**입니다. 하락 진입 10,000원, 무효 경계 10,200원, 목표 9,000원도 **5**입니다. 가격을 특정 종목에 대한 제안으로 사용하지 않습니다.

목표가 구간이면 가까운 목표·먼 목표의 손익비를 둘 다 보여 줍니다. 최대 손익비를 선택하지 않습니다. 목표를 임의의 손익비 배수로 역산하지 않습니다. 위험이 0, 순서가 거꾸로, 가격이 0·null·무한대, 단위가 다르면 계산을 보류합니다.

보상과 사전에 정한 손실 폭을 비교한다는 일반 개념은 [CME의 위험·보상 예시](https://www.cmegroup.com/education/courses/trade-and-risk-management/the-2-percent-rule)를 참고했습니다. 해당 자료의 계좌 비율이나 계약 수 산정은 이 모듈에 도입하지 않았습니다.

### 비용 처리

기본 출력은 `gross`이며 수수료·세금·슬리피지가 미반영입니다. 특정 세율이나 증권사 요율을 하드코딩하지 않았습니다. 호출자가 아래 세 항목을 **명시적으로 원/주 단위**로 모두 제공하고 출처·기준일을 지정한 때만 `net`을 추가합니다.

```text
net 위험 = gross 위험 + 진입비용 + 손절청산비용
net 보상 = gross 보상 − 진입비용 − 목표청산비용
net 손익비 = net 보상 / net 위험
```

비용이 보상보다 커서 `net` 보상이 음수이면 음수 그대로 표시합니다. 0이나 양수로 바꾸지 않습니다. 미래 기준일의 비용·음수 비용·출처 없는 설정은 무효이며 gross만 남습니다. 이 설정은 **입력한 비용만** 반영하므로 모든 실제 비용이 포함되었다는 보장은 아닙니다. 현재 UI에 새로운 증권사 비용 설정 기능이나 실제 세율 조회는 추가하지 않았습니다.

## 날짜·호가·갭·재생의 안전 경계

입력은 정규화된 `{date, open, high, low, close, volume, dataMetadata?}` 일봉 배열입니다. 정렬 방향은 양쪽 모두 허용하고 날짜 중복·OHLC 모순·음수/누락 거래량은 거부합니다. 실제 0 거래량은 허용합니다.

- `asOfDate`와 `completedThroughDate` 또는 `closedThroughDate`를 명시해야 합니다. 현재 시각으로 완료 여부를 추정하지 않습니다.
- 미래 또는 미완성 상한 뒤의 봉은 사용하지 않습니다. 과거 재생 시 이후 봉을 바꿔도 과거 결과는 바뀌지 않아야 합니다.
- 후보의 `knownAt`, `availableAt`, 피벗의 `confirmedAt`, 돌파 확인일, 경사진 목선의 기준일 중 가장 늦은 시점 이후만 추가 관측에 사용합니다. 피벗 원래 날짜에 이미 후보를 알았던 것처럼 취급하지 않습니다.
- 출처와 원천 거래일을 명시해야 합니다. 원천일이 관측 스냅샷보다 미래이거나 완료 봉보다 과거면 시나리오를 보류합니다. 원천에 더 최신 미완성봉이 함께 있었다면 완료봉 날짜와 분리해 표시합니다.
- 호가 규칙이 없으면 소수 참고값을 멋대로 반올림하지 않습니다. 같은 기준일·단위·출처로 제공한 하나의 호가 격자에 맞는지만 확인합니다. 가격 구간별 호가 변경이나 주문 적법성 검증을 대신하지 않습니다.
- 이전 종가에서 다음 시가가 돌파선을 뛰어넘으면 갭 관측을 남기고 체결 가격은 null로 둡니다. 일봉 안에서 손절·목표 모두 관측되면 순서를 만들어 내지 않습니다.

갭에서 손절 가격과 실제 체결 가격이 달라질 수 있다는 설명은 [SEC Investor.gov의 주문 교육](https://www.investor.gov/introduction-investing/general-resources/news-alerts/alerts-bulletins/investor-bulletins-15)을 참고했습니다. 실제 주문을 제출하거나 해당 미국 주문 규정을 국내 주문 API에 적용하는 구현은 없습니다.

## 검증 결과와 한계

`tests/analysis-price-scenarios.test.cjs`는 TEST_ONLY 고정 숫자로 방향별 수식, 명시 비용, 가격 구간 양 끝, 충돌 후보 보존, 경계 접촉과 종가 무효 구분, 갭, 호가 미확인, 피보나치 참고 보존, 미래봉 배제·과거 재생, 실제 신규 패턴·엘리엇 모듈 출력 연결을 검사합니다.

실제 제공처 호출, 시장 수익성 검증, 체결 시뮬레이션, 실계좌·주문 호출은 수행하지 않습니다. 과거 원천 데이터가 별도로 검증·제공되지 않은 상태에서 “백테스트 성공”이나 “수익성 향상”을 주장하지 않습니다.
