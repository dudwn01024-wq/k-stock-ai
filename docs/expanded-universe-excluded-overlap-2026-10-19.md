## 최소 변경과 완전성 근거

운영 코드는 `services/recommendationUniverse.js` 한 파일만 변경했다.

1. 이미 기존 공식 분류를 통과한 제외 종목이며 유효한 제공 거래일이 있는지 내부 관측 기록에 남긴다. 이름이나 코드의 모양으로 분류하지 않고, 공식 분류표와 검증기는 변경하지 않는다.
2. 동일 시장의 바로 이전 페이지에서 나온 코드이고 안정적인 이름·유형·시장·거래일 해시가 같을 때만, 공식 제외 종목의 재등장을 후보 밖 겹침으로 처리한다. 같은 페이지·다른 시장·비인접 페이지·식별 충돌은 계속 실패한다. 제공처의 ETF/우선주 라벨만으로 이 새 예외를 활성화할 수 없다.
3. 겹친 제외 종목을 후보에 넣거나 기존 후보 값을 갱신하지 않는다. 공식 유형 HTTP를 추가하지 않고, 고유 제외 종목과 공식 근거도 중복 집계하지 않는다. 허용된 공식 제외 겹침은 `excludedOverlapCount`로 구분한다.
4. 겹친 제외 종목의 값도 **전체 페이지 max/min에 그대로 포함**한다. 그 값이 컷오프 이상이면 해당 페이지는 시장 완료 증거가 되지 않는다. 페이지 전체 검증·새 코드 진행·양 시장의 엄격한 max<컷오프 또는 실제 시장 끝·고유 적격 500개 조건을 그대로 요구한다.
5. 보통주 및 검증되지 않은 유형의 겹침에는 기존 컷오프 아래 예외만 적용한다. 컷오프 미확정, 기존/새 후보 값의 동점·초과, 전체 경계 페이지가 컷오프에 닿는 경우는 계속 실패한다. 499개나 상한 10회에서 증명할 수 없으면 부분 결과를 성공으로 내보내지 않는다.

공식 제외가 검증된 종목은 값이 갱신돼도 후보 집합에 속하지 않는다. 그 재등장을 처리해도 선택 가능한 고유 종목 집합이나 선택된 종목의 데이터는 바뀌지 않는다. 해당 페이지의 고유 후보는 전부 검증하며 raw 페이지 경계는 낮추지 않는다. 이는 기존 제공처 순위 페이지 계약 아래의 완전성 근거이며, 시장 전체의 원자적 스냅샷은 계속 `snapshotConsistency: NOT_PROVEN`이다.

같은 페이지를 재조회하거나 자동 재분석하는 경로를 추가하지 않았다. 최대 목록 요청 10회·100행·순차 페이지 조회를 유지했다. KIS의 2초 간격·공유 예산·최신성·영속 원장과 가격·추세·거래량·뉴스·AI·저장 판정은 기준 버전과 byte-identical이다.
