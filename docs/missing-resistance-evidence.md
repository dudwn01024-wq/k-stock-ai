# Preserve independent detail conditions when resistance is unavailable

The supplied 171090 screenshot shows the preserved original strategy reporting only `저항선` as an unconfirmed price-plan input. It does not establish an ATR shortage. Its October 19 supply is explicitly historical on October 20. The original OHLCV rows and response are unavailable; the particular market-data reason for the missing resistance remains unconfirmed.

`calculateSupportResistance` examines the latest 80 bars, uses pivots with two neighbors on each side, clusters their levels, and selects resistance strictly above the latest daily close. No qualifying upper pivot can be a legitimate result even with 130 valid bars and a positive ATR/support. An older higher peak outside that window does not supply a current resistance. Missing/short input and invalid fields are other possible paths. The chart producer and strategy consumer agree on `supportResistance.nearestResistance.price`; the source inspection found no static naming mismatch. Existing safe logs contain supply events, not the original chart series.

The confirmed implementation defect is the strategy's early return before independent technical and market evaluations. One missing resistance erased trend/volume/news assessments even when their inputs were available.

The change is restricted to a positive current price/support, positive finite ATR, and unavailable resistance, after the existing raw-source integrity guard. It invokes the unchanged technical and market evaluators and retains their own unavailable/pending/caution states. The strategy remains unavailable and `DATA_INSUFFICIENT`, with an explicit resistance reason. Every entry/target/stop/reward/risk/ratio/rate stays null; risk/reward and execution assessments stay null, and `isEntryAllowed` remains false. No substitute resistance or target is generated. Invalid-source, other missing price-input, invalid-plan and complete-plan behavior is unchanged.

The current frontend already preserves these conditions as original reference information. Its cache reconciliation still forces WAIT, excludes prior-day supply, masks stale price plans, and does not refresh chart/news timestamps. The patch does not modify the chart engine, providers, API request paths, universe loader, scoring, AI, quota/ledger, schedules, account/order or Risk Manager.
